# Lattice Studio Cockpit

This optional Roblox Studio plugin is the lightweight Studio cockpit and the
Studio-required half of Lattice's native Rust companion bridge. It is not an
MCP server and contains no indexing, policy, routing, database, trace analysis,
or AI logic.

The plugin initiates loopback HTTP reports to the Rust daemon. It does not launch
Studio. Only the Edit DataModel owns a session, preventing Studio's play-mode
plugin clones from registering as independent windows.

## Configuration

1. Enable **Allow HTTP Requests** in Studio for the project being inspected.
2. Start `lattice-daemon` with `--studio-bridge-bind 127.0.0.1:13471`.
3. Reload installed plugins if the plugin was installed while Studio was
   already open, then open **Plugins → Lattice**. The plugin discovers the
   loopback bridge and pairs automatically; there is no key to paste.

The pairing credential is short-lived, generated by the daemon, and retained
only in the plugin's running session. The bridge remains loopback-only. The
legacy `LATTICE_STUDIO_BRIDGE_TOKEN` environment variable is optional for older
clients and is not required by the plugin.

The v1 bridge command implementation is deliberately read-only: Studio state
and selection. Source reads, mutations, and destructive actions remain on the
Studio MCP/ChangeSet path until the bridge receives equivalent policy,
precondition, verification, and rollback integration.

## Build

Fusion is pinned as a Git submodule at `v0.3-beta` commit
`77e603534ff4013f4049611826ff0309d6000b15`. Native build tools are pinned in
the repository `rokit.toml`.

```text
stylua --check plugin/LatticeCompanion
selene plugin/LatticeCompanion
rojo build plugin/LatticeCompanion/lattice-companion.project.json \
  -o plugin/LatticeCompanion/dist/LatticeCompanion.rbxm
```

Production does not import the `Fixtures` module. Recorder controls remain
disabled when the daemon reports Flight Recorder unavailable; the plugin never
synthesizes Connected, Healthy, Indexed, or Recording states.
